How to test your keyboard

A key that does not respond is one of the most annoying faults you can own, because it is invisible until the moment you need it. There are five practical ways to test a keyboard, and they are not equally useful: some tell you whether the operating system receives your key presses, others tell you whether the hardware is physically alive. This guide compares them so you can pick the right one for the fault you are actually seeing.

The five methods at a glance

Every method below answers a slightly different question. Read the table first: it tells you which one you need for the symptom you have, and saves you from testing in the wrong order.

Method Takes Proves
1. Browser test 10 seconds The OS delivers your key presses to a web page
2. Built-in OS test 2 minutes The OS recognises the key and can report its code
3. BIOS / UEFI screen 5 minutes The hardware works before the OS loads
4. Dedicated app 5 minutes Key codes, scancodes and every key at once
5. Physical check 10 minutes Nothing electrical — only contamination and damage

Method 1: the browser test (fastest)

Start here. Open the keyboard test in your browser, click once so the page has focus, and start typing. Every key you press lights up green, and the counters on the right show how many presses you made and how many different keys you reached.

This is enough to answer the most common question: "is my keyboard broken, or is it just this application?" If every key lights up here, the keyboard is delivering key events correctly and the problem is somewhere else — a shortcut, a language layout, a stuck modifier, or the app itself.

Two details make the difference between a useful test and a frustrating one. First, the tester distinguishes unique keys from total presses, so a key that fires twice when you press it once is visible as an anomaly rather than hidden by a large counter. Second, it shows modifier keys (Shift, Ctrl, Alt, Meta) separately, which is how you catch a modifier that is stuck down — the classic cause of "my keyboard types in caps all the time".

A browser test cannot tell you about switch wear, because a worn switch still produces a valid key event. It can, however, tell you about ghosting, double-fire and modifier problems, which together account for most of what people describe as "the keyboard is broken".

Method 2: the built-in operating system test

Both major desktop operating systems ship with a keyboard diagnostic that reports the raw scan code of every key. It is hidden, but it is there.

On Windows

Press Win + Ctrl + O. A small panel appears that shows the character, the scan code and the virtual key code of whatever you press next. Press the key you suspect:

  • The character lights up → the key reaches Windows. The fault is in the application or in a shortcut.
  • Nothing happens → the key never reaches the OS. Continue with method 3.

A useful companion is On-Screen Keyboard (search for it in the Start menu). Clicking a key on the on-screen keyboard types that character. If the on-screen keyboard types a character but the physical key does not, the fault is unambiguously in the keyboard.

On macOS

There is no direct equivalent shortcut, but the Keyboard Viewer (Accessibility → Keyboard → Accessibility Keyboard, or Input menu → Show Keyboard Viewer) highlights the key you press in real time. If a key never highlights, it never reaches the system.

Method 3: the BIOS / UEFI setup screen

This is the only method that tests the keyboard without the operating system. Restart the machine and repeatedly press Del, F2 or Esc during boot to enter the setup screen. The BIOS has its own text input fields that work long before Windows or macOS loads.

Type into the BIOS fields. This one test separates two very different problems:

  • The key works in the BIOS → the hardware is fine. The fault is in the operating system, a driver, or a software remapping.
  • The key does not work in the BIOS → the fault is in the hardware itself: a failed switch, a torn membrane or a broken cable.

On a laptop with a built-in keyboard, also test the external keyboard port with a second keyboard. If the external keyboard works and the internal one does not, the problem is the internal keyboard assembly — the membrane, the flex cable or the keyboard backlight ribbon — not the individual key.

Method 4: a dedicated keyboard test application

A desktop application gives you more detail than a browser: it shows the raw scancode, highlights keys simultaneously, and often records how many keys are held down at the same time. That last number is how you detect ghosting — a gaming keyboard that reports three keys when you press two.

The practical value is that these tools can distinguish an intermittent fault that only appears after several minutes of use, and they keep a log you can paste into a support request. If your key only fails intermittently, a test you run for thirty seconds will not find it — run a browser test and leave it open while you work.

Method 5: the physical check

When every electronic test passes but the key still misbehaves, the problem is physical. This applies mostly to laptops, where dust, sugar residue and liquid are common causes.

  1. Power off and unplug before opening anything. On a laptop, disconnect the battery if it is removable.
  2. Look for residue. Sticky keys are almost always sugar or spilled liquid. Clean with 90% isopropyl alcohol and a soft brush.
  3. Check the keycap and the switch. A keycap that has been twisted or re-seated repeatedly can sit a fraction of a millimetre off, so the switch never fully closes.
  4. Look at the flex ribbon cable on a laptop. A connector that is not fully seated causes exactly this symptom: several keys dead at once, in a pattern.
  5. Test again with method 1 before and after.

If several keys die at the same time, that pattern points at the membrane or the ribbon cable rather than at individual switches — the opposite of what most people assume. See the diagnostics guide for the full decision tree.

Which method should you use?

A short decision path, based on the symptom:

  • One key never responds → method 1, then 2, then 3.
  • Several keys dead together → method 1, then 3, then 5 (look at the ribbon cable).
  • Key repeats or fires twice → method 1. The tester counts presses and unique keys separately, so the mismatch is obvious.
  • Wrong characters appear → method 1. Check which modifier is stuck.
  • Key works in another app but not in one → it is a software problem. Stop testing hardware.

Frequently asked questions

Does this online keyboard test send my keystrokes anywhere?

No. The tester runs entirely in your browser. Key presses are handled by a script that only draws them on screen; nothing is uploaded, logged or stored on a server. You can confirm this by opening your browser's network tab while you type: there is no request containing what you type. The details are in the Privacy Policy.

Why does my keyboard type the wrong letters?

Three causes account for almost every case: a stuck modifier key (Shift or Caps Lock left on), a different keyboard layout selected in the operating system than the one printed on the keycaps, or a software remapping application. Run the browser test and look at the modifier row: if Shift stays highlighted when you are not touching it, that is the answer. If every key lights up correctly but the character printed is different, compare your layout with the physical legends.

Can I test a laptop keyboard without opening it?

Yes. Start with the browser test and the BIOS screen. Both work on a closed laptop. A BIOS test that fails on the built-in keyboard but passes on a USB keyboard confirms the fault is in the internal keyboard assembly, which is what tells you whether a repair is worth it.

Why does my key only fail sometimes?

Intermittent faults are common with a worn switch, a marginal cable contact or a wireless receiver losing the signal. A short test will not find them. Leave the browser test open in a second window while you work and watch the counter: if the key that misbehaves never lights up even once, the fault is confirmed and reproducible enough to act on.

Does the tester work with wireless keyboards?

Yes. The browser receives whatever the operating system delivers, and the operating system receives whatever the wireless receiver delivers. If a wireless keyboard drops the connection, its keys simply stop appearing in the tester, which is itself useful information: it tells you the fault is in the radio link, not in the switches.
